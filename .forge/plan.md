# 가운데 이음의 M3 나사를 스냅 후크로 교체

## 목표 / 비목표
- 목표: 겹친 다리 이음의 앞뒤 M3 접시머리 나사 2개를 없애고, 오른쪽 조각의 겹친 다리(혀)에 달린 스냅 후크로 바꾼다. 후크는 다리 높이의 가운데에만 둔다. 그래서 길이 방향으로 당겨도, 위아래로 움직여도 빠지지 않는다. 나사 없이 길이 방향으로 밀어 넣기만 하면 조립이 끝난다.
- 비목표: 분리 가능한 구조(관통 창, 해제 장치), 혀가 안쪽으로 밀리는 것을 막는 별도 구조, 세로 손가락 후크, 처마형 지붕(열린 후속 후보 `fu-b77e70e10287`), 출력 방향 변경, `dust-cover.solidcraft` 수정, AI 생성 렌더 이미지(`images/macbook-clamshell-*`) 재생성.

## 확정된 결정 (그릴링 결과)
- 스케치는 위에서 본 다리 단면이다(세로 = 길이 X, 가로 = 두께 Y). 파란색은 왼쪽 조각의 바깥 판, 빨간색은 오른쪽 조각의 겹친 다리(혀)다.
- 영구 결합으로 한다. 걸쇠 자리는 왼쪽 바깥 판 안쪽 면에 막힌 홈으로 파서 겉에서는 보이지 않는다. 걸쇠 면은 90°다.
- 혀 길이 `LAP`는 8mm에서 16mm로 늘리고, 턱 돌출은 0.6mm로 한다. 휨 변형률은 1.5·2.4·0.6/16² ≈ 0.84%다. 근거: 8mm이면 약 3.4%가 되고, X 방향으로 쌓는 출력이라 층간 방향으로 휜다. 혀 뿌리(이음선 쪽)는 둥글게 처리한다.
- 혀가 안쪽(맥북 쪽)으로 밀리는 것은 막지 않는다. 걸쇠 면이 90°라 당기는 힘에는 턱을 빼내는 성분이 없고, 혀의 탄성이 걸림을 유지한다.
- 치수(모두 파일 맨 위 파라미터):
  - 턱 높이 범위 Z 6~11mm (중심 8.5)
  - 턱 돌출 0.6
  - 턱 길이 X 3mm. 혀 끝 쪽은 45° 경사, 이음선 쪽은 90° 걸쇠 면
  - 턱 위치는 혀 끝
  - 홈은 턱보다 사방 `SEAM_CLEAR`(0.05) 크고 깊이 0.65
- 조립 경로는 길이 방향 밀어 넣기 하나뿐이다. 아래에서 올려 끼우는 경로는 없어진다.
- 나사 관련 파라미터와 형상(`SCREW_HOLE_D`, `SCREW_HEAD_D`, `PIN_Z`, `pin_hole()`)은 제거한다. `PIN_Z`의 8.5는 턱 중심 높이 파라미터로 대체한다.

## 진실의 원천
- 용어: 없음 (`.forge/CONTEXT.md` 미사용)
- 관련 ADR: 없음
- 완료 정의(DoD): `F=/Applications/FreeCAD.app/Contents/Resources/bin/freecadcmd`, 작업 디렉터리는 저장소 루트다.
  1. `$F dust_cover.py`가 종료 코드 0으로 끝나고 두 STL을 다시 쓴다.
     - 사전 상태: 통과(기존 모델). 회귀 가드다.
  2. `$F check_cover.py | grep -c '^PASS'`의 결과가 5이고, `grep -c '^FAIL'`의 결과가 0이다. (e) 줄은 "후크"를 보고하며 다음을 모두 만족해야 한다.
     - 접시 자리와 나사 구멍 자리가 메워져 있다.
     - 오른쪽 조각을 +X, +Z, -Z로 각각 0.5mm 옮기면 왼쪽 조각과 겹친다(걸림).
     - 휨 변형률이 1.0% 이하다.
     - (b)는 조립 상태의 간섭이 0인지만 본다. 아래에서 올리기, 옆에서 밀기 경로 검사는 삭제한다.
     - 사전 상태: PASS 5, FAIL 0이지만 (e)가 "나사"를 보고하므로 순방향 조건을 만족하지 않는다. 확인 명령은 `$F check_cover.py | grep '^PASS (e)' | grep -c 후크`이고, 사전 값은 0이다.
  3. 틀린 값으로 FAIL이 나는지 확인한다. `dust_cover.py`의 턱 돌출을 0으로 바꿔 두 스크립트를 실행하면 (e)가 FAIL이어야 한다. 확인한 뒤 값을 0.6으로 되돌리고 다시 실행해 DoD 2를 만족시킨다. 결과는 run 기록에 남긴다.
     - 사전 상태: 해당 없음(후크 검사가 아직 없음).
  4. `grep -cE '나사|M3|SCREW|PIN_Z|올려 끼' README.md dust_cover.py check_cover.py render_images.py`가 파일마다 0이다.
     - 파인더 명령: `grep -nE '나사|M3|SCREW|PIN_Z|아래에서 올려|올려 끼' README.md check_cover.py render_images.py dust_cover.py`
     - 사전 상태: README 19곳, check_cover.py 3곳(120·121·136행), render_images.py 1곳(54행), dust_cover.py 10곳(SCREW·PIN_Z·pin_hole·나사 주석). 순방향 검사다.
     - 예외: 도브테일→나사로 바뀐 경위를 설명하는 문장이 필요하면 "나사" 대신 다른 표현을 쓴다. 이력은 git에 있으므로 README에서는 지운다.
  5. README의 이음 절, 이동별 차단 표, 치수 표, 검증 표의 (b)·(e), 조립 절차, 파라미터 표, 알려진 한계가 후크 구조를 설명한다. 조립 절차는 "길이 방향으로 밀어 넣으면 딸깍 걸린다"로 바꾸고, 파라미터 표에는 새 후크 파라미터 이름을 적는데, 그 이름이 `dust_cover.py`에 실제로 있어야 한다.
     - 사전 상태: 나사를 설명함.
  6. `render_images.py`로 `images/` 아래 FreeCAD 캡처 이미지(assembled-iso, assembled-under, assembly-exploded, side-view, top-view, print-orientation)를 다시 만든다.
     - 사전 상태: 나사 구멍이 있는 이미지.
  - 사용자 확인(UAT): 실물 출력 전이라 자동 검증이 불가능하다. 출력 후 밀어 넣었을 때 딸깍 걸리는지, 혀 뿌리가 갈라지지 않는지 눈으로 확인한다.
